════════════════════════════════════════════════════════════
  The int4 decode GEMV computes 8 int4 values with the dp4a route:
    unpack int4 -> int8, then 2x v_dot4_i32_iu8  (2 dot instrs / 8 values)
  But the silicon has v_dot8_i32_iu4: 8 int4 values in ONE instruction.
  => the kernel is leaving the native path on the table. That's the gap.
