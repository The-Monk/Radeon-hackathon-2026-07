# The self-producing demo — made *by* the thing it demonstrates

The Track 2 submission needs a demo video. Instead of a screen-recording with human voiceover, **the optimized Omni model produces and narrates it itself, on one AMD Radeon R9700, entirely locally.** The submission artifact is generated by the submission — which is exactly the claim Track 2 scores: *core inference runs locally on the Radeon GPU.* It doubles as multimodal-content-creation evidence for Track 1.

## The Omni is already assembled
Lemonade ships composite "Core" models bundling every modality — no from-scratch build:

| Composite | LLM (script/agent) | Image | STT | TTS |
|---|---|---|---|---|
| **`Gwen-Agent-Core`** ← use this | Qwen-AgentWorld-35B-A3B (the agent brain) | Flux-2-Klein-9B | Whisper-Large-v3-Turbo | **kokoro-v1** |
| `Gemma_Core` | Gemma-4-26B-A4B | Flux-2-Klein-9B | Whisper | kokoro-v1 |
| `LMX-Omni-52B-Halo` | Qwen3.6-35B-MTP | Flux-2-Klein-9B | Whisper | kokoro-v1 |

`Gwen-Agent-Core` is the one: its LLM *is* the Track 2 agent brain, so the model narrating the video is the same model being demonstrated.

### Component roles (use each where it's strong)
| Role | Model | Why |
|---|---|---|
| Agent brain + VO script | **Gwen-Agent-Core** (Qwen-AgentWorld-35B-A3B) | tool-calling; it's the Track 2 agent |
| Narration (TTS) | **kokoro-v1** (82M, Apache-2.0, ONNX) | tiny, local, proven — 24 kHz MP3 on the card |
| Image **generation** | **Flux-2-Klein-9B** | title/section visuals |
| **Thinking** + image **understanding** | **Ternary-Bonsai-27B-Q2_0** | ternary, ~one-card, fast reasoning — Bonsai is a thinking/vision model, NOT a narrator or tool-caller, so it plans/reasons, it doesn't voice |

### Registering a custom Omni (one command)
The four composites above were built with Lemonade's collection mechanism:
```bash
lemonade pull user.Bonsai-Think-Omni --recipe collection.omni \
  --components Qwen-AgentWorld-35B-A3B-GGUF-UD-Q8_K_XL Ternary-Bonsai-27B-Q2_0 Flux-2-Klein-9B-GGUF kokoro-v1
# components must already be registered; agent LLM does tool-calling+VO, Bonsai does thinking/vision
```

## Pipeline (every stage local, one card)

```
                      ┌─────────── all on the R9700 via Lemonade :13305 ───────────┐
 agent runs the       │  LLM         Flux-2-Klein      kokoro-v1        ffmpeg      │
 optimization  ──►  script  ──►   title/section  +  narration MP3  ──►  stitch  ──► demo.mp4
 (real terminal      (writes    frames (visuals)    (TTS, proven)      (audio+     │
  capture)            the VO)                                           video)      │
                      └────────────────────────────────────────────────────────────┘
```

1. **Capture** the real agent run — `hyperloom` CLI + the optimizer-agent finding & fixing a kernel gap — as terminal video (`asciinema`/`ffmpeg -f x11grab`). This is the substance: the optimization actually happening.
2. **Script** — the LLM (Gwen-Agent-Core) writes the voiceover from the run's transcript.
3. **Visuals** — Flux-2-Klein generates title/section cards; interleave with the terminal capture.
4. **Narrate** — `narrate.sh` → kokoro-v1 TTS → MP3 per section. **Proven:** an 11.6 s clip renders to a valid 24 kHz MP3 on the card.
5. **Assemble** — `build-demo-video.sh` stitches frames + narration with `ffmpeg` → `demo.mp4`.

## Files
- `narrate.sh` — local TTS wrapper (kokoro-v1 via Lemonade). Runnable now.
- `build-demo-video.sh` — assembly skeleton; the terminal-capture + Flux steps run in a GPU session.

## Why it's not a gimmick
It collapses three proofs into one artifact: **(1)** multimodal generation (Track 1), **(2)** local-on-Radeon inference (Track 2's hard requirement), **(3)** the optimization visibly working (Track 2's 40 GPU-adaptation points). The narration you hear is the same silicon and the same model stack the agent runs on.
